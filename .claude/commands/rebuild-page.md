# <Page Name> Page Rebuild Instructions

I want to completely replace the content of the <page_name> page with the new content that I will provide.

## Critical Requirements

### 1. Full Project Analysis (Mandatory)

Before making any implementation decisions:

- Analyze ALL existing HTML files in the project.
- Do not limit the review to only a few pages or components.
- Explore section designs across the entire codebase.
- Identify all available design patterns and section variations.
- Select layouts based on the content requirements of each specific section.

### 2. Strict Content Preservation (Highest Priority)

⚠️ This is a mandatory requirement.

- Use the content exactly as provided.
- Do NOT modify, rewrite, rephrase, shorten, expand, improve, optimize, or generate alternative content.
- Do NOT change any headings, subheadings, paragraphs, bullet points, button text, labels, captions, or CTA text.
- Do NOT add any new content.
- Do NOT remove any content.
- Do NOT skip any section.
- Do NOT merge sections unless explicitly instructed.
- Every piece of content I provide must appear on the final page exactly as provided.
- The final implementation must contain 100% of the supplied content with no omissions and no alterations whatsoever.

### 3. Section Design Selection

For each content section:

- Choose the most suitable section design from the existing HTML files.
- Match the design style to the content type.
- Evaluate all available design options before making a selection.

Examples:

- Hero content → Best hero section design available.
- Features content → Best feature section design available.
- Statistics content → Best stats section design available.
- Testimonials → Best testimonial design available.
- CTA sections → Best CTA design available.

### 4. No Duplicate Section Designs

- Each section design/layout may be used only once on this page.
- Avoid repeating the same section structure throughout the page.
- If multiple feature sections exist, use different feature section variations from different files.
- Ensure strong visual variety while maintaining overall consistency.

### 5. Content Completeness Validation

Before completing the task:

- Verify that every provided section has been implemented.
- Verify that no content has been skipped.
- Verify that no content has been modified.
- Verify that all text, buttons, images, cards, labels, and CTAs are present.
- Ensure the final page is a complete representation of the supplied content.

### 6. Design & Development Standards

- Preserve the original styling and design quality of selected sections.
- Reuse existing classes and structures wherever possible.
- Maintain responsiveness across desktop, tablet, and mobile devices.
- Ensure smooth visual flow between sections.
- Keep brand consistency with the rest of the website.
- Follow existing project conventions and coding standards.

## Expected Workflow

- Analyze all HTML files in the project.
- Identify all available section designs.
- Map each provided content section to the most suitable existing design.
- Ensure no section layout is reused.
- Implement the page using the selected designs.
- Verify that every piece of provided content exists exactly as supplied.

## Final Validation Checklist

Before marking the task complete, confirm:

- All HTML files were reviewed.
- Every provided content section is included.
- No content was modified.
- No content was skipped.
- No additional content was added.
- No section design was reused.
